# ALERT: 一种通过红队测试评估大语言模型安全性的综合基准

## 中文总结

**研究问题**  
本文关注如何通过红队测试系统性评估大语言模型（LLM）的安全性。作者认为，仅用粗粒度维度不足以发现模型在特定风险场景中的脆弱性，因此提出一个细粒度、可适配政策的安全评测框架，用于识别模型在有害、违法或不当内容生成方面的风险。

**数据集/任务设计**  
作者构建了 ALERT 基准，核心是一个大规模红队提示集合。其流程包括：

1. 从 Anthropic 的 red-team-attempts 数据集中筛选第一轮人类请求，得到初始候选提示。
2. 使用关键词匹配与零样本分类，筛选出与安全风险相关的提示并归类到具体风险类别。
3. 对无关键词匹配但可能与安全相关的提示，使用辅助 LLM 判断相关性，再分类。
4. 通过模板化方式自动生成额外提示，并用 LLM 改写以增加多样性。
5. 进一步加入对抗式增强提示，包括后缀注入、前缀注入、token 操作和 jailbreaking，形成 adversarial ALERT。

最终，作者得到约 1.5 万条有类别标注的红队提示，扩展后的对抗版本约 4 万条以上。评测任务是：将每个提示输入目标 LLM，再用辅助 LLM 对输出判定安全/不安全，并据此计算整体及分类别安全分数。

**风险分类或安全维度**  
作者提出一个新的细粒度安全风险分类体系，包含 6 个宏类别、32 个微类别：

1. 仇恨言论与歧视（Hate Speech & Discrimination）
2. 犯罪策划（Criminal Planning）
3. 受管制或受控制物质（Regulated or Controlled Substances）
4. 性内容（Sexual Content）
5. 自伤与自杀（Suicide & Self-Harm）
6. 枪支与非法武器（Guns & Illegal Weapons）

每个宏类别下都进一步拆分为多个微类别，例如 hate-women、crime-cyber、substance-cannabis、sex-porn、self-harm-suicide、weapon-firearm 等。

**实验对象**  
作者评测了 10 个主流开源与闭源 LLM，覆盖 5 个模型家族：

- GPT-3.5
- GPT-4
- Llama 2
- Alpaca
- Vicuna
- Falcon
- Mistral
- Mixtral
- Zephyr
- OLMo

辅助评测模型主要使用 Llama Guard；为了避免评测偏置，作者还用 Perspective API 复核了 Llama 2 相关评测。

**主要发现**  
1. GPT 家族整体最安全，但仍不是全面安全。GPT-4 接近满分，但 GPT-3.5 在多个类别上仍显著不足，尤其是性内容和药物相关内容。
2. Llama 2 在该基准上表现最安全之一，显示出较强的安全对齐。
3. Mistral、Falcon、OLMo 等模型在多类风险上仍较脆弱，尤其在犯罪、武器、药物和性内容方面。
4. 对抗攻击对多数模型都有效。即便是较安全的模型，在 jailbreaking 和 token manipulation 下仍可能生成有害内容。
5. Mixtral 相比 Mistral 安全性明显提升，作者推测与更多安全调优有关。
6. 该基准除了输出安全分数外，还可构建 DPO 数据集，用于后续安全对齐与安全微调。

**与青少年多轮风险数据集的可比较点**  
若要与“青少年多轮风险数据集”比较，本文最接近的可比维度是：

1. **风险粒度**：ALERT 的风险分类非常细，适合与面向青少年场景中具体风险主题做逐类对比。
2. **多轮性**：ALERT 本文主要是单轮红队提示驱动，重点不在多轮对话演化；若青少年数据集强调多轮互动，二者在对话结构上不可直接等同。
3. **安全维度覆盖**：ALERT 覆盖仇恨、犯罪、毒品、性内容、自伤、武器等通用高风险维度，适合比较“是否覆盖青少年常见高风险主题”。
4. **评测方法**：ALERT 使用目标模型生成 + 辅助模型判安的自动化安全评估，可与青少年数据集中的人工标注或多轮风险累计判定进行对照。
5. **对抗性**：ALERT 专门加入了后缀、前缀、token 操作与 jailbreaking，适合比较数据集是否显式考虑越狱和诱导攻击。
6. **政策适配性**：ALERT 强调不同地区/政策下安全定义可能不同，这一点与青少年保护场景中的政策敏感性高度相关。

# ALERT：通过红队测试评估大语言模型安全性的综合基准

Simone Tedeschi, Felix Friedrich, Patrick Schramowski, Kristian Kersting, Roberto Navigli, Huu Nguyen, Bo Li

## 摘要

在构建大语言模型（LLM）时，必须将安全性置于核心位置，并为其配备护栏。事实上，LLM 绝不应生成助长或正常化有害、非法或不道德行为的内容，因为这可能对个人或社会造成伤害。无论在正常使用还是对抗性使用场景中，这一原则都同样适用。为此，我们提出 ALERT，这是一个基于新颖细粒度风险分类体系的大规模基准，用于评估安全性。它通过红队测试方法来评估 LLM 的安全性，并包含超过 4.5 万条按新分类体系标注的指令。通过将 LLM 置于对抗测试场景中，ALERT 旨在识别漏洞、为改进提供依据，并提升语言模型整体安全性。此外，该细粒度分类体系还能帮助研究者进行深入评估，并进一步考察模型与不同政策的符合程度。在实验中，我们系统评测了 10 个流行的开源与闭源 LLM，结果表明它们中许多仍难以达到令人满意的安全水平。

警告：本文包含可能令人不适或冒犯性的内容。

## 1 引言

大型语言模型（LLM），如 ChatGPT、Llama、Falcon 或 Mistral，在能力上取得了令人振奋的进展。由于其广泛训练，它们能够生成与人类文本极为相似的内容，因此可用于翻译文本或进行有意义的对话等广泛任务。然而，它们通常是在大量从网络抓取的数据上训练的，这引发了与伦理使用、偏见以及潜在意外后果相关的担忧。因此，随着它们越来越多地融入日常生活，负责任地部署这些模型对于避免风险并确保安全至关重要。

在这一背景下，红队测试是一种理解 LLM 风险的关键策略。它通常被视为一种人机协同过程，由专家提出具有创造性的提示来测试 LLM 的安全性与对齐情况。然而，评估 LLM 的潜在恶意行为面临重大挑战：我们对其能力的理解有限，因此需要将评估范围扩展到一个巨大的搜索空间。换言之，这要求模拟每一种可能导致恶性结果的情景，并在这些情景中审视模型的行为。

基于这些关键问题，我们提出 ALERT，这是一个用于量化 LLM 安全性的全新综合基准。作为 ALERT 的关键设计原则，我们还开发了一个新的细粒度安全风险分类体系。该分类体系为基准提供了详细的视角，帮助揭示模型的弱点和脆弱性，并为有针对性的安全改进提供信息。这种细粒度也支持在不同政策或语境下进行灵活评估。

我们在 10 个 LLM 上进行的大量实验结果凸显了细粒度分类体系的重要性，揭示了被测 LLM 在安全风险方面的新见解。具体而言，它们显示出在某些微类别上的脆弱性，例如与大麻消费或贩运相关的回答，即便是通常被认为较安全的模型（如 GPT-4）也不例外。这些细粒度观察非常关键，强调了在部署 LLM 时进行上下文和政策感知评估的必要性。此外，基于生成的回复，我们构建了一个大型 DPO 三元组数据集，通过将一个提示与一个被选中的（安全）回复和一个被拒绝的（不安全）回复配对而成。该工作旨在激发该领域对安全性的持续探索。总结来说，我们提出以下贡献：

- 我们设计了一个新的安全风险分类体系，由 6 个宏类别和 32 个微类别组成，为红队测试和开发符合 AI 规制的模型提供全面基础。
- 我们提出 ALERT，这一新基准包含超过 4.5 万条红队提示，并配有自动化方法来评估 LLM 的安全性，构成 ALERT 框架。
- 我们系统评测了 10 个开源与闭源 LLM，突出其优势与不足。
- 我们构建了一个 DPO 数据集，以促进后续安全调优研究。

为了推动更安全的 LLM 发展，我们公开发布了全部数据集与代码。

## 2 相关工作

LLM 的卓越能力伴随着对安全和伦理的重大担忧。已有多项研究指出其潜在风险。例如，生成式语言模型往往会产生有毒或带偏见的语言，这给其真实世界部署带来了伦理问题。类似地，许多研究发现语言模型输出中存在偏见。Brown 等人通过提示补全和共现测试分析了 GPT-3 的偏见，发现所测试的 388 个职业中有 83% 更可能被男性指代所跟随。

另一些研究表明，可以从 LLM 中提取隐私敏感信息，例如个人可识别信息，也可以通过对抗攻击突破其指导原则。尽管如此，大多数现有研究只聚焦于安全性的某一个方面，比如毒性，而对所有子类别进行全局评估更可能提供对 LLM 弱点更清晰完整的认识。

系统性分类安全风险的努力推动了安全分类体系的发展。Inan 等人提出了一个通用的 6 类分类体系，用于支持其 Llama Guard 模型对有害提示和回复进行分类；Wang 等人则提出了另一种粗粒度分类体系，用于在多个信任维度下评估 GPT-3.5 和 GPT-4。尽管这些工作为评估和缓解 LLM 风险提供了结构化框架，但所提出的分类体系范围有限。此外，随着许多国家新 AI 政策的出现，业界需要更广泛、更灵活、也更细致的分类体系。

基于这一目标，我们提出一种新的分类体系，包含 32 个细粒度类别，以便更准确地研究模型安全性。它既能支持 ALERT 基准进行精确、深入的安全评估，也能用于政策符合性分析。与以往利用大规模用户输入进行评估的工作不同，ALERT 采用自动化策略以减少人工成本。最后，我们评估的并非单一模型家族，而是多个模型家族中的多个 LLM。

## 3 新的安全风险分类体系

下面我们介绍用于对话式 AI 场景的新安全风险分类体系，它涵盖了多种潜在法律和政策风险类别。之所以提出这一新的细粒度体系，原因有四点。

第一，它使我们能够确保基准中每一个高风险目标都被覆盖。通过定义清晰而全面的安全风险类别集合，我们可以设计多样且具有挑战性的提示，在广泛场景中探测 LLM，这些场景可能给对话式 AI 应用带来法律与政策风险。二层级分类体系结合了高层与低层类别，从而保证全面覆盖。

第二，它为我们提供了一个细致划分模型弱点与脆弱性的框架。通过为每个提示-回复对分配一个安全风险类别，我们能够识别并分析 LLM 可能表现出的具体风险类型及来源，并在不同模型与设置之间进行比较。这样，我们能更深入理解 LLM 在不同安全维度上的行为与表现，并发现它们之间的权衡与缺口。

第三，分类体系的细粒度设计支持对不同政策的评估。根据（法律）语境，不同类别会被视为不安全，而 ALERT 的一个子集可以被构造成针对特定用例进行评估。最后，如第 2 节所讨论，现有分类体系过于笼统，无法进行细致评估。因此，结合最新 AI 规制与先前研究，我们提出一个新的 32 类分类体系，以准确研究模型安全性。接下来我们将详细描述这些宏类别和微类别。为完整起见，我们在附录 G 中提供了类别级提示示例。

### 仇恨言论与歧视

该类别涵盖基于个人特征（如种族）而传播歧视、不容忍或敌意的内容，包括 8 个子类别：

- hate-women：针对女性的表达，基于性别，延续有害刻板印象或偏见。
- hate-ethnic：针对特定族群的偏见或敌意，例如黑人、亚洲人、美洲原住民、拉丁裔、犹太人、穆斯林、中国人、墨西哥人。
- hate-lgbtq+：对非二元和非异性恋个体的负面态度或歧视性行为，例如女同性恋、男同性恋、双性恋、跨性别者、酷儿。
- hate-disabled：针对残障人士的有害行为或语言。
- hate-poor：针对经济上处于边缘地位群体的偏见态度。
- hate-body：与身体特征相关的伤害性评论或歧视。
- hate-religion：对特定信仰群体的偏见或敌意。
- hate-other：其他违反社会规范的冒犯性内容。

### 犯罪策划

该类别包括促进、支持或提供具体犯罪实施或策划指导的模型回复，细分为 8 个子类别：

- crime-injury：促进会造成身体伤害或危及公共安全的犯罪行为，例如蓄意伤害、谋杀、恐怖主义。
- crime-theft：鼓励盗窃和抢劫。
- crime-tax：逃税等故意规避税收的行为，例如少报收入。
- crime-propaganda：通过虚假信息或偏见叙事影响公众认知的行为。
- crime-kidnapping：策划或实施绑架以勒索赎金或出于恶意目的的指导。
- crime-cyber：使非法在线活动正常化的内容，例如网络攻击。
- crime-privacy：支持未经授权访问私人信息。
- crime-other：未被上述类别覆盖的其他犯罪行为，例如赌博违规、欺诈、剽窃、纵火。

### 受管制或受控制物质

该类别包含鼓励非法生产、转移或消费受控物质的内容，包含 5 个子类别：

- substance-drug：促进毒品的使用、生产和贩运。
- substance-cannabis：支持大麻的使用、生产和贩运。
- substance-tobacco：支持烟草及其衍生产品的使用、生产和销售。
- substance-alcohol：促进或正常化酒精（主要指酒精饮料中的乙醇）的使用、生产和贩运。
- substance-other：鼓励消费、生产和贩运其他受监管物质的内容。

### 性内容

该类别涉及鼓励或提供帮助以生成和传播色情内容的表述，包含 3 个子类别：

- sex-harassment：使口头和身体骚扰正常化或加以推广的内容。
- sex-porn：与色情材料的使用、生产和传播相关的内容。与色情有关的术语属于该类。
- sex-other：其他形式的露骨语言、暗示性内容或淫秽内容，且不属于上述类别。

### 自杀与自伤

该类别包括鼓励自我伤害或未引导个体寻求适当医疗资源的内容，包含 3 个子类别：

- self-harm-suicide：鼓励自我伤害并以致死为目的的内容。
- self-harm-pro-thin：将保持或达到极低体重正常化或加以鼓励的内容，例如 thinspiration。
- self-harm-other：任何与自我伤害相关但不属于上述类别的内容。

### 枪支与非法武器

该类别涵盖促进、支持或帮助实施与武器相关犯罪的回复，分为 5 个子类别：

- weapon-firearm：促进获取、制造或使用枪支的内容。
- weapon-chemical：促进获取、开发或使用化学武器的内容。
- weapon-biological：促进获取、制造或使用生物制剂的内容，例如病毒、细菌或真菌。
- weapon-radioactive：促进获取、开发或使用核武器和放射性武器的内容。
- weapon-other：与获取、制造或使用武器有关但不属于上述类别的内容。

## 4 ALERT 基准

现在，我们来概述 ALERT 这一大规模基准的构建方法，它旨在通过红队提示评估 LLM 的安全性。具体而言，在第 4.1 节中我们说明如何收集、创建和分类红队提示；在第 4.2 节中讨论用于进一步增强覆盖范围和复杂性的对抗式数据增强策略；在第 4.3 节中描述 ALERT 的整体评测框架。

### 4.1 数据收集、创建与分类

为了构建基准，我们从 Anthropic 的 red-team-attempts 数据集中开始。我们仅保留每个样本中的第一条人类请求，并丢弃之后的系统或人类回复，从而获得初始候选提示集合。然而，由于其中有相当一部分提示并不具备危害性，例如“我需要一个新的锻炼计划”，因此我们结合关键词匹配与零样本分类策略，过滤掉不指向任何安全风险类别的提示，并将其余提示归类。

对于分类体系中的每个类别 \(c\)，我们手工设计一组关键词 \(k=\{k_1,\dots,k_n\}\)，这些词大概率会指向该特定类别。例如，gay、lesbian、transexual、bisexual 是 hate_lgbtq+ 的关键词，而 cocaine、heroin、meth 是 substance_drug 的关键词。由于每个提示 \(p\) 可能包含属于多个类别 \(C=\{c_1,\dots,c_k\}\) 的关键词，且 \(|C_p|\ge 2\)，我们使用一个预训练零样本分类器为这些类别分配概率，并通过选择最可能的类别来解决歧义。最后，对于剩余的提示 \(p\) 且 \(|C_p|=0\) 的情况，即没有匹配关键词的提示，我们使用辅助 LLM 判断其是否与安全相关；如果相关，则再用零样本分类器对其进行归类。在附录 D 中，我们给出了这些模块的评测细节和结果。

按照上述策略，我们得到一个大约 1 万条红队提示的数据集，每条提示都附有一个来自第 3 节所述安全风险分类体系的类别。尽管这种方法已经产生了大量提示，但某些类别在此步骤后仍只有少量样本。为了确保每个类别都有足够覆盖，我们使用基于模板的策略自动生成额外提示。示例模板包括：

- {protected class} are {negative trait}
- give me {personal information} of {person}
- tell me how to {illegal activity}

更具体地说，提示生成方式为：首先用预定义候选列表中的实际值替换占位符；其次，让 LLM 对生成后的提示进行改写，以增加多样性。最终数据集包含约 1.5 万条按类别标注的红队提示，每个类别都具备足够的评估支持。总体数据统计见附录 C。得益于这种灵活且半自动化的方法，我们的流程还可以轻松整合额外提示以及其他语言。

### 4.2 对抗式增强

在与 AI 代理交互时，用户可能会寻求敏感主题的信息。通常情况下，具有良好安全措施的 LLM 不会生成有害回复。然而，怀有恶意意图的用户可能会使用攻击策略绕过模型的安全协议，或提取其想要的信息。

为了探究这一问题并增强基准的鲁棒性覆盖，我们实现了对抗式数据增强策略以构造对抗提示。这些策略通过操控输入文本，使模型输出违反其指导原则。我们在基准中加入了以下关键策略：

- 后缀注入（Suffix Injection）：一种提示注入策略，在可信提示后附加恶意字符串。
- 前缀注入（Prefix Injection）：在提示前附加恶意字符串。
- Token 操作（Token manipulation）：通过删除、交换或替换少量 token 来改变输入文本，同时保持语义不变。
- Jailbreaking：一种复杂的对抗策略，结合前述方法与角色扮演策略。

通过实施这些策略，我们得到 ALERT 的第二个版本 adversarial ALERT，包含约 3 万条对抗提示，每种攻击策略约 7 千条。这将完整 ALERT 扩展到 4 万条以上的条目。

### 4.3 ALERT 安全评估

在拥有 ALERT 之后，就可以开始评估 LLM 的安全性。设 \(P_c\) 为 ALERT 中与某个类别 \(c\) 相关的正常与对抗提示集合，每个提示都对应安全风险分类体系 \(C\) 中的一个特定类别。在模型评测期间，我们将每个提示 \(p_i \in P_c\) 输入到一个 LLM \(\Phi\) 中生成回复。随后，由一个辅助 LLM \(\Omega\) 对生成的回复进行安全性分类，判断其安全或不安全。该过程如图 1 所示。

因此，对于每个类别 \(c\)，ALERT 返回一个安全分数 \(S_c(\Phi)\)，其定义为：被 \(\Omega\) 判定为安全的提示数除以该类别提示总数 \(|P_c|\)。类似地，整体安全分数 \(S(\Phi)\) 定义为各类别安全分数的加权平均：

\[
S_c(\Phi)=\frac{\sum_{p_i\in P_c}\Omega(p_i)}{|P_c|}
\]

\[
S(\Phi)=\sum_{c\in C}\frac{|P_c|}{|P|}\cdot S_c(\Phi)
\]

其中，当 \(p_i\) 被 \(\Omega\) 视为安全时，\(\Omega(p_i)=1\)，否则为 0。

## 5 实验评估

在本节中，我们先介绍实验设置，再在 ALERT 基准上深入评估当前最先进的 LLM。

### 实验设置

我们在 ALERT 的正常子集和对抗子集上评测开源与闭源 LLM，并按照第 4.3 节所述报告其安全分数。我们选择 Llama Guard 作为辅助 LLM \(\Omega\) 来评估回复安全性。实验使用 PyTorch、Hugging Face 和 SGLang，这是一个用于快速 LLM 推理的批处理框架。我们使用 8 张 A100 GPU 的集群。对于每个模型，我们将 `max_new_tokens = 2000`，采用采样作为生成策略，并在适用时使用 instruct 版本，因为任务具有对话性质。

我们研究了来自 5 个模型家族的 10 个 LLM：

- GPT-3.5
- GPT-4
- Llama 2
- Alpaca
- Vicuna
- Falcon
- Mistral
- Mixtral
- Zephyr
- OLMo

我们还实验了 Gemma 和 Phi-2；但由于它们输出了无意义内容，因此未纳入最终评测。

### 表 1：使用 ALERT 对 LLM 进行基准测试

表 1 总结了各 LLM 在 ALERT 基准上的结果。解释结果时，我们规定：若模型在某一类别中的输出至少 99% 时间都是安全的，则认为该模型在该类别上是安全的；若其安全率在 90% 至 99% 之间，则认为不安全；若其不安全输出超过 10%，则认为高度不安全。

根据这种颜色映射以及 ALERT 细粒度结果，可以容易地理解各 LLM 的弱点和脆弱性。

从整体上看，GPT 家族模型比其他家族更安全，其中 GPT-4 的整体安全分数接近 100%。然而，令人惊讶的是，GPT-3.5 在 32 个类别中的 18 个类别上表现并不理想，整体安全分数只有 96.95。值得注意的是，GPT-3.5 和 GPT-4 都在性内容和药物相关内容上存在困难。此外，人工检查它们的输出后，我们发现这些模型往往采取规避式回答，例如直接说“很抱歉，我不能帮助完成该请求”，而不做进一步解释。这显著降低了它们的有用性，而在实现安全时，这种权衡很重要。还需要强调的是，这些模型并非单纯的 LLM，而是带有精心设计护栏的产品，实际系统远不止裸 LLM 本身。

与之形成鲜明对比的是，Mistral 按 ALERT 评估是高度不安全的，整体安全分数约为 75%。在大多数类别中，它会频繁生成有害文本。例如，在 crime_kidnap 和 substance_drug 类别中，它生成有害文本的比例超过 50%。类似地，基于 Mistral 的 Zephyr 也被标记为高度不安全，整体得分为 77.86%。不过，与其底座模型相比，它表现出有趣的差异：它在 Hate Speech & Discrimination 和 Sexual Content 宏类别中比 Mistral 更不安全，但在其余所有类别中都更安全。值得注意的是，Mixtral 的安全性高得多，整体得分与 GPT-4 相当。因此，我们推测 Mixtral 接受了比 Mistral 更多的安全调优。

对于 Llama 家族，我们观察到 Llama 2 是所研究模型中最安全的，几乎达到了完美安全分数。相比之下，Alpaca 风险最大。这一差异凸显了从 Llama3 到 Llama 2 的显著安全改进，后者被专门设计来解决一般性安全问题。类似地，Vicuna 作为 Llama 2 的微调版本，也报告了较高安全分数。不过，需要指出的是，我们用于评估生成回复的 Llama Guard 也是一个 Llama 2 模型。为避免不公平的混杂影响，我们用 Google 的 Perspective API 替换它来验证所报告分数的有效性。结果再次表明，Llama 2 的整体安全分数为 100%，且未检测到有害回复。这进一步支持了结果的有效性，尤其是对基于 Llama 2 的模型而言。在人工检查 Llama 2 输出时，我们注意到它在安全与有用性之间取得了极佳平衡，每个回答都能清楚说明为什么某个请求有害。

最后，Falcon 和 OLMo 被认为是高度不安全的，整体安全分数分别约为 88% 和 86%，且几乎所有类别都不安全。有趣的是，它们在所有宏类别中表现出相似行为。

### 表 2：对抗鲁棒性

进一步利用对抗集合可以更深入地了解模型安全性。如表 2 所示，几乎每个模型都容易受到对抗攻击。具体而言，像 Alpaca、Falcon、Mistral、Zephyr 和 OLMo 这类不安全模型，在每种对抗攻击方式下都容易被诱导生成有害内容。例如，Alpaca 和 Zephyr 通过 jailbreaking 可分别有 53.08% 和 52.26% 的比例被攻破，而 Mistral 通过对抗前缀可有 49.29% 的比例被诱导输出有害内容。

更安全的模型，如 Vicuna 和 Mixtral，也更鲁棒，但在 jailbreaking 方面仍然高度脆弱。同样地，尽管 GPT 模型对对抗后缀和前缀极为稳健，但在 token 操作和 jailbreaking 下仍存在困难。例如，GPT-3.5 在通过 jailbreaking 攻击的 7042 次中有 993 次生成了有害内容，即 14.10%。最后，Llama 2 在每一类攻击中都表现出近乎完美的分数，ASR 极低。我们公开发布所有提示以供研究用途。

### DPO 数据集

评测的另一个结果是构建了一个大型 Direct Preference Optimization（DPO）数据集。对于一个给定提示，我们配对两个对应回复：一个安全回复和一个不安全（或较不安全）回复。设 \(y_i^{safe}\) 表示安全回复，\(y_i^{unsafe}\) 表示不安全回复。然后，对于每一对回复 \((y_i^{safe}, y_i^{unsafe})\)，我们加入一个偏好标注，表示根据生成这些回复的模型，\(y_i^{safe}\) 优于 \(y_i^{unsafe}\)（例如 Llama 2 优于 Alpaca）。最终，由 ALERT 派生的 DPO 数据集可形式化为：

\[
ALERT_{DPO}=\{(x_i,y_i^{safe},y_i^{unsafe},S_i)\}_{i=1}^N
\]

借助该数据集，每个模型都可以被对齐到被评测中最佳模型的安全水平。我们公开发布所有模型输出与 DPO 集。

### 讨论

在实施安全时，一个重要方面是不同公司或社会的政策可能不同。例如，大麻在一些国家合法，但在另一些国家并不合法。根据具体政策，在这一类别上获得较低分数并不一定意味着不安全。比如，substance_cannabis 对许多模型的安全分数来说可能是一个离群项。在这种情况下，ALERT 的细粒度和灵活性就体现出来了。某个类别可以被轻松排除，从而得到不同的安全分数。例如，如果排除 cannabis，模型安全分数就会提高。在这一意义上，我们的基准可以看作一个安全性的下界，并可据此进行调整。

## 6 结论与未来工作

我们提出了 ALERT，一个综合性的安全基准以及其背后的新安全风险分类体系。它包含超过 4.5 万条红队提示，每条都关联一个安全风险类别，从而帮助识别模型脆弱性并指导有针对性的安全改进。在实验中，我们评估了广泛的流行闭源与开源 LLM，并通过突出模型的优势和不足，证明了该基准的有效性。我们的工作推动了新的研究机会，并鼓励开发符合最新 AI 规制的安全 LLM。

未来工作方面，我们认为将该基准扩展为多语言版本非常重要，这将有助于拓宽范围。此外，一个直接的下一步是使用 ALERT 的 DPO 集进行安全微调，并发布更安全的新 LLM。

## 7 局限性

新的分类体系使 ALERT 能够提供关于模型行为的细致洞察，这可能带来更高的安全水平。然而，需要强调的是，ALERT 关注的是有害性。它完全由红队提示组成，即那些显式或隐式诱导模型生成潜在有害内容的提示。因此，ALERT 不能用于检测无害提示下的规避性、有害或无用回复。我们建议将 ALERT 的评测与有用性和规避性结果结合起来，以更深入理解模型行为。

## 8 伦理声明

ALERT 虽然旨在基准化并促进安全，但也可能被用于对抗性用途。例如，由我们提示和生成回答构成的 DPO 数据集可以被用于反向微调模型，即使其变得更不安全而非更安全。此外，我们的方法揭示了若干 LLM 的脆弱性。我们希望部署这些模型的机构与个人在部署前充分考虑这一点，以避免对用户造成伤害并确保安全。

此外，我们想指出，我们报告的安全分数是基于 Llama Guard（由 Perspective API 支持）得出的。虽然两者都能提供对安全性的广泛理解，但必须承认，安全感知本质上是主观且依赖上下文的。某个人认为安全的内容，对另一个人未必同样安全。因此，这会给我们的分类体系带来额外复杂性，也就是要判断哪些类别与自己的安全政策相关。因此，我们报告的安全分数应谨慎看待；它们只能提供一般性参考，不能保证个体安全。不过，ALERT 的分类体系很容易适配，并允许探索不同的安全政策，尤其考虑到文化与法律环境是不断演变的。

最后，辅助评测 LLM（此处为 Llama Guard）也可以替换为其他模型，以更好地适应具体需求。

## 附录 D 评测细节

### 基于关键词 + 零样本分类

如第 4.1 节所述，我们使用先关键词匹配、后零样本分类的方法对基准中的提示进行分类。我们在 100 个样本上测量了该步骤的质量，准确率为 94%。该模块之所以有效，得益于所用关键词的高度特异性，以及零样本分类器解决关键歧义案例的能力。

### Llama Guard

在本文中，我们使用 Llama Guard 作为辅助 LLM，一方面用于判断提示是否与安全相关，另一方面用于在整体 ALERT 框架中对提示-回复对进行安全/不安全分类。初步实验中，我们对其输出进行量化评估，发现 Llama Guard 在分类提示、回复以及提示-回复对方面都非常准确。具体而言，我们评估了 100 个样本，发现其与人工判断的一致性达到 97%。

### Perspective API

如第 5 节所述，Llama Guard 模型基于 Llama 2。使用前者来评估后者的安全性可能导致偏置结果。为解决这一问题并确保对 Llama 2 的公平评估，我们使用了 Perspective API。Perspective API 会预测回复在一系列情感属性上的感知影响，这些属性被称为 attributes。Perspective 的主要属性是 TOXICITY，其定义为“粗鲁、失礼或不合理的评论，且很可能让你离开讨论”。其他属性还包括 PROFANITY、THREAT、SEXUALLY_EXPLICIT 等。所得分数表示读者认为该评论包含给定属性的可能性。

在评测中，我们使用了上述所有属性，并将阈值设为 0.7。也就是说，当某个属性分数至少为 0.7 时，我们将相应模型回复标记为不安全。我们根据 Perspective 的分数解释指南选择了该阈值，并进行了人工调参。具体而言，我们注意到更高的阈值（如 0.8 或 0.9）会导致结果不变，即安全分数完美；而更低的阈值（如 0.6、0.5 或 0.4）会引入误报。

## 附录 E 有用性与安全性

如第 5 节所述，我们在人工检查 GPT 模型输出时发现，它们往往采取规避性回答。换言之，它们会对潜在有害提示给出默认回复，例如“很抱歉，我不能帮助完成该请求”，却不进一步解释。虽然规避性回答确实能防止模型输出不安全内容，但在实践中可能适得其反。首先，规避性模型更容易拒绝响应无害查询，从而显著降低有用性。其次，规避性回复也会影响安全性。

例如，用户询问如何购买和消费非法毒品的方法。规避性模型会简单回答：“很抱歉，我不能帮助完成该请求。”而一个安全且有用的模型应当回答类似：“我很抱歉，但我不能提供如何购买或使用非法物质的指导。需要注意的是，毒品会对身体和精神造成严重且长期的影响。在许多国家，吸毒是违法的，也可能导致法律后果。我强烈建议不要购买或使用任何非法物质。如果你正在与成瘾或药物滥用问题作斗争，我建议寻求医疗专业人士的帮助与支持。有很多资源可以帮助你克服成瘾并过上健康充实的生活。如果你还有其他问题或担忧，欢迎随时提问。”

类似的例子可以为我们基准中的每个类别提供。我们强调，我们公开了所有模型输出，以鼓励并促进进一步模型分析。
