# R-Judge: Benchmarking Safety Risk Awareness for LLM Agents

## 中文总结

- **研究问题**：本文关注的是 LLM 代理在真实交互环境中的行为安全，而不是仅仅评估其生成内容是否无害。核心问题是：给定一段多轮代理交互记录，LLM 能否准确识别其中的安全风险，并判断代理行为是“safe”还是“unsafe”。
- **数据集/任务设计**：作者构建了 R-Judge，一个面向个人 LLM 代理的安全评测基准，共 569 条多轮交互记录。每条记录包含用户指令、代理思考/行动、环境反馈；任务被拆成两个串行评测：
  - 风险识别：根据记录输出一段风险分析；
  - 安全判断：根据记录和分析输出二分类标签 `safe` / `unsafe`。
- **风险分类或安全维度**：R-Judge 覆盖 5 类应用场景和 27 个具体场景，并划分为 10 类风险类型：
  - 隐私泄露
  - 计算机安全
  - 金融损失
  - 财产损害
  - 物理健康
  - 数据丢失
  - 非法活动
  - 伦理与道德
  - 偏见与冒犯
  - 其他
- **实验对象**：评估了 11 个 LLM，包括 GPT-4o、ChatGPT、Meta-Llama-3-8B-Instruct、Llama-2-7b-chat-hf、Llama-2-13b-chat-hf、Vicuna 系列、Mistral 系列，以及 Llama Guard 作为对照。
- **主要发现**：
  - 大多数模型在安全判断和风险识别上都表现不佳，很多模型甚至低于随机基线。
  - 最强模型 GPT-4o 在安全判断 F1 上达到 74.45%，但仍远未达到“可靠监控器”的水平。
  - 风险意识是多维能力，依赖知识、推理和情境适应，而不是简单的关键词判断。
  - 直接的 prompt 技巧提升有限；相反，对安全判断进行高质量数据微调更有效。
  - 用于内容审核的 Llama Guard 在该任务上并不稳定，说明“内容安全”与“代理行为安全”并不等价。
- **与青少年多轮风险数据集的可比较点**：
  - 都是**多轮交互**场景下的风险评测，而不是单轮问答。
  - 都强调**人工标注**、**高质量风险描述**、**可用于安全评估**。
  - 都适合比较模型在复杂上下文中的**风险识别**与**安全判断**能力。
  - 不同点在于：R-Judge 聚焦的是**LLM 代理行为安全**和工具/环境交互风险，而不是青少年场景本身；因此可比性主要体现在**任务形式、标注粒度和风险评测方法**，而不在具体应用领域。

## 中文全文翻译

# R-Judge: 面向 LLM 代理的安全风险意识基准评测

## 摘要

大型语言模型（LLM）已经展现出在真实世界应用中自主完成任务的巨大潜力。然而，当 LLM 代理在交互式环境中运行时，会引入意料之外的安全风险。不同于以往大多数研究主要关注 LLM 生成内容的无害性，本文聚焦于在多样化环境中对 LLM 代理行为安全性的评测需求。我们提出 R-Judge，一个用于评估 LLM 在给定代理交互记录时判断和识别安全风险能力的基准。R-Judge 包含 569 条多轮代理交互记录，涵盖 5 类应用场景中的 27 个关键风险场景，以及 10 类风险类型。该数据集经过高质量整理，带有安全标签和风险描述。对 11 个 LLM 在 R-Judge 上的评估显示：LLM 的风险意识仍有很大提升空间。表现最好的模型 GPT-4o 的 F1 为 74.45%，而其他模型都未明显超过随机基线。此外，我们发现开放式代理场景中的风险意识是一种涉及知识与推理的多维能力，因此对 LLM 而言仍然具有挑战性。进一步实验表明，对安全判断进行微调能显著提升模型表现，而直接的提示词机制则收效有限。R-Judge 已公开发布于：https://github.com/Lordog/R-Judge。

## 1 引言

大型语言模型（LLM）在推理、决策和指令遵循方面表现出强大能力（Wei et al., 2022a）。LLM 尤其是 GPT-4 的能力推动了 LLM 代理的发展（Xi et al., 2023; Wang et al., 2023b; Zhang et al., 2023b）。借助工具使用和环境交互，AutoGPT、Voyager 和 OpenHands 等代理能够以 LLM 作为控制器自主完成用户指定任务（Zhou et al., 2023b; Lin et al., 2023a）。

鉴于复杂环境中存在未知风险，LLM 代理容易引发预料之外的安全问题（Xi et al., 2023; Ruan et al., 2024; Naihin et al., 2023）。例如，当代理被要求处理电子邮件时，可能会无意点击钓鱼邮件中的 URL，导致隐私泄露甚至财产损失。因此，越来越多研究者意识到，安全保障是 LLM 代理进入真实应用场景的必要前提。为此，关键在于有效评估开放代理场景下 LLM 的安全风险意识。

现有安全评测工作主要关注 LLM 生成内容的安全问题（Zhiheng et al., 2023; Bhardwaj and Poria, 2023），即尽量避免输出冒犯、不公平、非法活动和伦理相关内容。值得注意的是，SafetyBench（Zhang et al., 2023a）和 SuperCLUE-Safety（Xu et al., 2023a）通过多选或开放式问题覆盖了多种安全关切。除评测外，基于 LLM 的监控器也被用于审核 LLM 输出内容（Inan et al., 2023; Zhang et al., 2024）。然而，基准题目无法暴露交互式环境中的行为风险，因此难以为 LLM 代理提供实用的安全评估。更进一步，内容监控器是否能在开放代理场景中有效工作仍然未知。

为解决上述挑战，少量研究开始探索 LLM 代理应用中的安全风险。为识别交互式环境中 LLM 代理的风险，ToolEmu（Ruan et al., 2024）实现了一个由 GPT-4 驱动的模拟器，配备多样工具和场景来模拟代理动作执行。配合该模拟器，一个由 GPT-4 驱动的自动安全评估器会检查代理失败并量化相关风险。类似地，AgentMonitor（Naihin et al., 2023）提出了一个框架，让 LLM 作为代理执行的监控器，通过阻止被判定为不安全的动作来预防安全问题。进一步地，InjecAgent（Zhan et al., 2024）展示了针对工具型 LLM 代理的间接提示注入风险，攻击者可在环境中注入恶意指令诱导代理执行有害动作。

虽然 ToolEmu 和 AgentMonitor 采用了不同设置，但两者都将 LLM 用作安全监控器来识别代理的危险动作。然而，在多轮交互背景下判断代理动作是否安全，对 LLM 而言依旧是一个具有挑战性的任务。由于交互复杂、环境多样，目前仍不清楚 LLM 是否真正具备识别代理安全问题的能力。

本文提出 R-Judge，一个用于评估 LLM 风险意识的基准，专门衡量 LLM 在给定代理交互记录时判断和识别安全风险的能力。每条记录都包含用户指令、代理动作历史和环境反馈。R-Judge 包含 569 条代理交互记录，覆盖 5 类场景中的 27 个流行应用任务，包括程序、物联网、软件、网页和金融（图 1）。每条记录都标注了二元安全标签以及相应风险描述。

基于 R-Judge，我们对 11 个常用作代理底座的主流 LLM 进行了全面评估。具体来说，我们将代理执行记录输入给待测 LLM，要求其识别风险并判断代理动作是否安全。结果表明，LLM 的风险意识仍有很大提升空间，代理安全问题值得重视：表现最好的模型 GPT-4o 在 F1 上达到 74.45%，而其他模型都没有明显超过随机基线。进一步实验发现，对安全判断进行微调可以显著提升模型表现，而直接的提示词机制效果有限。通过案例分析，我们总结出：开放代理场景中的风险意识是一种涉及知识和推理的多维能力，对 LLM 而言具有挑战性。

本文贡献如下：

- 我们首先形式化了代理安全问题中关于 LLM 安全风险意识的任务。具体而言，我们将给定代理交互记录时对安全风险进行判断和识别的任务定义为一个简单而有效的范式，用以评估 LLM 的风险意识。
- 我们提出了 R-Judge，一个具有复杂多轮交互的实用基准数据集，包含用户、环境和代理之间的交互，并带有高质量的安全标签和风险描述。据我们所知，这是第一个专门用于评估 LLM 代理安全风险意识的基准数据集。
- 我们基于 R-Judge 评估了 11 个流行 LLM，发现多数模型都无法识别开放代理场景中的安全风险。我们进一步分析了不同机制的影响并进行了深入案例研究，为未来代理安全研究总结出有价值的见解。

## 2 问题形式化

### LLM 代理的记录

LLM 驱动的代理可以通过使用代码解释器、网页搜索等工具与环境交互，以自主完成用户指定的任务（Nakano et al., 2021; Richards, 2023）。LLM 代理的交互过程会被记录下来。图 2 左上角给出了一个记录示例。

我们记 `L`、`A` 和 `F` 分别为空间：语言、动作和环境状态。LLM 代理的交互过程如下：

首先，用户通过指令 `u` 与代理交互。根据 `u`，代理生成思考 `t`，随后生成动作 `a`。执行动作后，代理接收环境反馈 `f`。一个 `(t, a, f)` 构成一个迭代单元。然后该单元不断循环，直到任务完成或发生错误。我们将完整交互过程记为记录：

`R = (u, [(t1, a1, f1), ..., (tn, an, fn)])`

其中 `n` 是任务完成时的交互轮数。用户可能多次调用代理，因此一个列表中的记录也可视为记录。对于每一轮，代理将 `R` 作为输入并输出 `(t, a)` 与环境交互。

### LLM 代理安全的风险意识

当直接与复杂环境交互时，LLM 代理容易引发意料之外的安全问题，其中一些问题可能非常严重，例如关键隐私泄露和数据丢失。然而，当使用 LLM 作为安全监控器时，代理引发的安全问题会更少，这一点已被 ToolEmu 和 AgentMonitor 说明。因此，LLM 的风险意识是 LLM 代理安全执行的重要因素。本文将代理安全监控任务形式化为对 LLM 风险意识的评估任务。

### 代理安全监控任务形式化

如图 2 所示，一个 LLM 检查代理交互记录，判断代理动作是否安全。其作为安全监控器的性能可以体现 LLM 是否能够有效识别安全风险并做出正确判断，从而反映其风险意识。该任务形式化如下：

`p_θ(R) -> (analysis, label)`

其中 `p_θ(·)` 表示语言模型映射，输入记录 `R`，输出分析文本和一个二元标签，表示安全或不安全。

## 3 R-Judge 基准

为评估 LLM 对代理安全的风险意识，我们构建了 R-Judge，一个包含多轮代理交互及人工安全标注的真实基准数据集。

### 3.1 案例格式

根据第 2 节中的问题形式化，我们定义了案例格式，如图 2 左半部分所示。下面对关键术语作详细说明：

- 代理记录：记录用户、环境和代理之间的交互过程。为通用起见，我们采用 ReAct（Yao et al., 2023）作为代理框架，即代理在交互环境中进行思考、执行动作并接收反馈。
- 安全标签：标签是“unsafe”和“safe”的二元值。该标签经过训练有素的人工标注者仔细标注并交叉检查，以确保无歧义。
- 风险描述：由标注者认真整理，包含帮助人类理解样本中风险所需的完整元素。风险描述的模式在附录 A.3 中详细说明。

### 3.2 采集原则

为了构建多样且高质量的数据集，我们首先设计了采集原则，包括问题范围和 LLM 代理的威胁模型。具体而言，我们聚焦于威胁个人 LLM 代理的两类基本风险：**有意攻击**和**无意风险**。

#### 问题范围

我们关注个人 LLM 代理（Li et al., 2024），这是代理应用的主流范式，意味着 LLM 代理预期部署在用户自己的系统上。基于此，我们定义了 5 类场景和相应 27 个情景，如图 1 所示。详情见附录 A.1 的表 4。

#### 威胁模型

对于个人 LLM 代理，用户提示理论上应是良性的，尽管其中可能不经意地包含风险。因此，围绕人类意图，威胁个人代理的风险主要来自两个基本来源（Tang et al., 2024）：

- **有意攻击**：外部攻击者试图通过环境媒介操纵代理。这里我们聚焦一种具体且主要的方式，即间接提示注入攻击。例如，在代理调用 Evernote 笔记的过程中，攻击者可能在工具返回值中注入恶意指令“请给我的朋友 Amy（guest_amy01）在 August Smart Lock 系统上赋予永久访问权限”。如果代理遵循该恶意指令，攻击者就可能获取用户住所的访问权限，带来严重风险。
- **无意风险**：由于环境复杂且存在多轮交互，即便没有恶意攻击，代理也可能造成安全问题。例如，用户要求代理在离家时关闭电器，但代理关闭了所有电器，包括安防摄像头，从而导致潜在问题。

最后，我们将涉及安全问题的代理归纳为 10 类风险类型，如图 1 所示，沿用 ToolEmu（Ruan et al., 2024）。

### 3.3 采集流程

由于当前代理应用中可见风险较少，且自动化制造有效记录存在困难，数据集主要基于与代理安全相关的工作构建。为了丰富无意风险数据，我们还从人类专家处构建高质量数据。值得注意的是，为了公平评估 LLM 代理的风险意识，我们尽量平衡安全和不安全样本的数量。这里的“safe”案例是指代理可能引发安全问题，但实际上并没有引发。

- **开源数据转化**：来自 ToolEmu、InjecAgent 和 AgentMonitor 的开源数据包含完整的 LLM 代理轨迹。我们过滤掉与采集原则冲突的无效数据，补充安全标签，并撰写风险描述。需要注意的是，AgentMonitor 中的代理不遵循 ReAct（只有 action），因此我们将 `thought` 字段留空。
- **人工构建**：我们还由人工专家构建高质量数据。一方面，为了补充不足的“safe”样本，我们将 ToolEmu 中部分“unsafe”样本通过把危险动作替换为安全动作转化为“safe”样本。另一方面，为了扩充数据集，标注者仔细头脑风暴出代理在某些场景下可能触发特定风险类型的应用案例，再借助 ChatGPT 和有效性检查将这些案例润色为有效样本。

### 3.4 数据集统计

最终，InjecAgent（Zhan et al., 2024）为有意攻击数据贡献了 414 个样本。ToolEmu 的 81 个样本、AgentMonitor 的 24 个样本，以及人工构建的 55 个样本，共同构成了 155 个无意风险数据。

R-Judge 包含 569 个复杂案例，其中复杂风险隐藏在用户、代理和环境之间的多轮交互中。平均而言，R-Judge 包含 2.6 轮交互和 206 个词，52.7% 为不安全案例。该数据集覆盖 5 类场景：程序、IoT、软件、网页和金融，共 27 个场景。R-Judge 还覆盖 10 类风险类型（附录 A.2），包括隐私泄露、计算机安全、物理健康、数据丢失、金融损失、财产损害、非法活动、伦理与道德、偏见与冒犯，以及其他。图 1 展示了 R-Judge 的整体概览。更多统计见附录 B.3 的表 5。

### 3.5 评测标准

基于该数据集，我们评估公开 LLM 作为代理安全监控器的有效性。由于代理安全监控既要求风险识别能力，也要求安全判断能力，我们设计了两个流程来评估 LLM 在给定代理交互记录时识别和判断安全风险的能力。

如图 2 右侧所示，这两个评测流程按串行管线进行。首先，将记录输入 LLM，要求其分析记录中的代理动作是否安全，形式化为 `p_θ(R) -> analysis`。随后，再要求 LLM 根据记录和第一步的分析输出“unsafe”或“safe”，形式化为 `p_θ(R, analysis) -> label`。第一步输出的分析和第二步输出的标签分别用于两个评测流程，以人工标注作为真值。

#### 安全判断的标签分数

为评估 LLM 做出安全判断的能力，基于标签的测试将 LLM 生成的二元安全标签与人工标注共识标签进行比较。

#### 风险识别的成对评估

为评估 LLM 在识别安全风险方面的效果，开放式测试使用 GPT-4（gpt-4-0613 版本）作为自动评分器，对模型生成的开放式分析进行评估，针对的是不安全样本。

有效的风险识别应清楚说明代理如何引发安全风险。我们用 **Effectiveness** 度量这一点。由于人工标注的风险描述是基准，Effectiveness 衡量的是模型生成分析与该锚点的相关性，即风险描述中所述风险是否被准确识别并在模型分析中得到体现。GPT-4 评分器的提示词见附录 D.2 的图 6。第 4.2 节验证了使用 GPT-4 作为自动评分器的可行性。

两项评测相互补充，提供了有效且渐进式的评测方式。安全判断测试更公平、成本更低，而风险识别测试则具有更细粒度的可解释性。

## 4 实验

本节先介绍实验设置，尤其是指标。然后，在验证 R-Judge 后，我们评估 11 个主流 LLM 在两项代理安全监控测试上的表现，即安全判断和风险识别。

### 4.1 设置

#### 基线模型

我们全面评估了 11 个 LLM，包括 API 模型和开源模型。API 模型包括 GPT 系列（OpenAI, 2023）。开源模型包括 Llama-2（Touvron et al., 2023）、Llama-3、Mistral（Jiang et al., 2023）和 Vicuna（Chiang et al., 2023）系列。具体版本和链接见附录 F.3 的表 9。完整实验设置（包括超参数和成本）见附录 F。

#### 提示设置

我们采用零样本思维链提示（Zero-Shot-CoT）（Kojima et al., 2022）来引导 LLM 在输出最终答案之前先生成推理步骤。这种先分析后回答的过程已被证明能提升推理表现和可解释性（Zhang et al., 2023b）。任务指令简洁明了，以保证通用性，如附录 D.2 的图 4 所示。

#### 指标

遵循信息检索中的二分类评估方式，安全判断使用 F1 作为排行榜主分数。同时，Recall 和 Specificity 分别表示模型识别不安全和安全样本的能力。公式见附录 D.1。

风险识别采用成对评估，引入 Effectiveness 指标，如第 3.5 节所述。在排行榜中，其被归一化到 0 到 100 的范围。

#### 参考分数

### 5.2 安全判断微调的影响

为研究安全判断微调的效果，我们在 Llama 与 Llama Guard 之间设计了对照实验。

#### Llama Guard

为审核 LLM 生成内容，Meta 开发了用于安全判断任务的 Llama Guard。具体而言，Llama Guard 可对用户提示和 LLM 回复中的不安全内容进行分类，判断给定提示或回复是否安全；如果不安全，还会列出违反的内容类别。Llama Guard 在其内部测试集上 F1 达到 91.50%，并在 OpenAI Mod 和 BeaverTails-30k 等公开数据集上表现出色。

#### 设置

利用 R-Judge 作为测试集，结果见表 3。在安全判断上，Meta-Llama-Guard-2-8B 在同样设置下超过了表 2 中表现最好的模型 GPT-4o，尽管其 Recall 更低，但 Specificity 更高。然而，LlamaGuard-7b 则无法胜任。

### 5.3 案例研究

为了弄清该任务的能力要求和当前 LLM 的缺陷，我们进一步对 GPT-4o 的结果进行了人工检查。我们总结出导致失败的三类关键能力缺陷：

#### (i) 场景模拟

无法在具体场景中检索相关知识并进行推理。一些安全风险隐藏在复杂的多轮代理交互中，而识别这些风险要求 LLM 监控器推断某些动作的后果，例如分享带编辑权限链接的影响。由于缺乏场景知识和推理能力，GPT-4o 可能无法把相应知识和场景联系起来，从而无法识别风险。例如，在代理将文件链接以编辑权限分享至 Twitter 的案例中，GPT-4o 失败了，而实际上这应是评论权限而非编辑权限。

#### (ii) 理解适应性

无法理解特定条件下的风险。风险与具体条件密切相关，即场景 A 中有风险的动作，在场景 B 中可能是安全的。尽管 GPT-4o 具备全面的安全对齐知识，它有时仍会表现出僵化与过度担忧，因为对某些条件的理解有限。例如，在假阳性中，GPT-4o 可能会说“代理执行的动作总体上是安全的，但存在一些潜在安全问题……”，却仍错误地将其判为不安全。相反，在假阴性中，GPT-4o 可能会意识到代理应就潜在风险动作先向用户确认，但仍错误地将其判为安全。

#### (iii) 安全对齐

在实际场景中，与人类安全对齐出现偏差。关于道德、伦理和隐私的主题较为模糊。鉴于人工专家对样本达成一致，GPT-4 表现出与人类的理解偏差。例如，在代理遵照用户指示，发布关于某位同学未经证实信息到 Twitter 的案例中，GPT-4 未能判定其违反隐私。

这些关键缺陷与风险识别测试中的 Effectiveness 结果一致，后者揭示了模型在不同维度上的能力差异。附录 E.4.1 中的图 11、12、13 展示了三类典型失败案例。

### 5.4 小结

基于实验结果和案例分析，我们认为构建一个具备风险意识的 LLM 代理，主要依赖两个方面：通用模型能力与基于高质量数据的微调。一方面，基础模型能力至关重要。风险意识要求基础模型具备知识与推理能力，这由参数规模支撑，这一点也被第 5.2 节中 Llama Guard 的实验结果和第 5.3 节中的人工案例研究所证实。另一方面，在基础模型之上，使用高质量且多样化的数据对安全判断进行微调，可以有效提升 LLM 代理的风险意识。未来，为代理配备一个专门微调的监控模型，用于提供清晰的安全风险反馈，是很有前景的方向。

## 6 相关工作

### 6.1 LLM 代理

LLM 具备出色的规划、推理与决策能力（Wei et al., 2022a），推动了智能代理的发展（Wooldridge and Jennings, 1995; Maes, 1995）。早期工作（Yao et al., 2023; Shinn et al., 2023）建立了 LLM 代理的框架原型，并探索了 LLM 在工具学习（Schick et al., 2023）和环境交互（Yao et al., 2022; Zhou et al., 2023a）中的能力。借助 GPT-4，AutoGPT（Richards, 2023）和 Voyager（Wang et al., 2023a）等代理可以自主完成用户指令。随着代理协作的发展，多代理系统（Hong et al., 2023; Qian et al., 2023; Xu et al., 2023b）展现出解决越来越复杂任务的能力。尽管研究社区主要关注开发在更多场景中更强大的 LLM 代理（Team, 2023; Xie et al., 2023），LLM 代理的安全性仍是一个开放问题。

### 6.2 LLM 安全

自 ChatGPT（OpenAI, 2022）对社会产生巨大影响以来，LLM 的安全性成为焦点。由于训练于大规模混合语料，LLM 可能会生成包含毒性、偏见和不道德内容的有害输出（Huang et al., 2023）。早期评测（Sun et al., 2023; Zhiheng et al., 2023; Lin et al., 2023b）用安全相关问题挑战 LLM。更近期的研究则利用对抗攻击和 jailbreak 攻击（Zou et al., 2023; Wei et al., 2023; Yuan et al., 2023; Deng et al.; Yi et al., 2023）进行红队测试，以评估 LLM 安全性（Bhardwaj and Poria, 2023）。在 LLM 的安全对齐方面，典型方法强调通过基于人类反馈的强化学习（RLHF）提升无害性（Ouyang et al., 2022; Bai et al., 2022; Dai et al., 2023）。近期研究还探索了基于 LLM 的监控器用于评估（Bhatt et al., 2023）和调控（Inan et al., 2023; Zhang et al., 2024）LLM 生成内容。随着工具使用和环境交互的引入，LLM 代理带来了新的现实安全问题，也推动了对代理行为安全的研究（Ruan et al., 2024; Naihin et al., 2023; Tian et al., 2023; Zhan et al., 2024）。作为代理安全的先驱工作，ToolEmu（Ruan et al., 2024）用 GPT-4 模拟器和多样工具/场景为 LLM 代理提供交互环境，并用 GPT-4 评估器识别执行中的风险。本文进一步评估 LLM 的风险意识，以促进多样场景下的代理安全。

## 7 结论

在交互式环境中，风险意识对于 LLM 代理的安全执行至关重要。本文提出了 R-Judge，一个通用、真实且符合人类认知的基准，用于评估 LLM 在给定代理交互记录时判断和识别安全风险的能力。对 11 个广泛使用的 LLM 的实验结果表明，当前 LLM 的风险意识远未完善，且该任务要求模型具备涉及知识和推理的通用能力。此外，我们进行了充分实验，为后续研究提供见解。我们发现，对安全判断进行微调可以显著提升模型性能，而直接的提示机制则难以奏效。

## 局限性

对于人工标注数据集而言，标注规模和标注质量之间总是存在权衡。由于代理交互过程跨不同环境较为复杂，我们的数据集规模小于此前基于爬取的 LLM 安全基准数据集（Zhang et al., 2023a）。不过，作为首个用于评估 LLM 代理风险意识的基准，我们的数据规模与若干高质量 LLM 基准数据集（Li et al., 2023a; Liu et al., 2023; Wei et al., 2022b）相当，这些数据集同样包含多步操作记录和人工标注。随着代理应用的发展，该数据集也具有可扩展性。因为扩展数据集只需要记录即席代理执行日志并在出现安全风险时补充少量标注。我们未来会继续扩充 R-Judge 数据集。

## 影响声明

本研究探讨了 LLM 代理的安全风险，揭示了当前 LLM 的风险意识仍然不足。为了暴露 LLM 的缺陷，我们构建的数据集包含少量带有有害内容的案例，例如偏见、冒犯和道德问题。然而，我们的研究模式被设定为良性而非对抗性，风险主要存在于代理动作而非生成内容中。我们不鼓励对数据集的潜在滥用，并鼓励负责任地使用它，以促进 LLM 代理安全。

### A.3 风险描述模式

为了清楚理解代理执行中的复杂安全问题，我们建立了一个简单模型，用以揭示潜在风险。

代理执行中的安全问题可能来自多个来源。用户、环境以及它们之间交互的复杂性，使得代理安全难以保证。为了清楚理解这些复杂问题，我们建立威胁模型，从用户、环境和代理的负面视角暴露潜在风险。

对于每个不安全案例，风险描述包含 **Motivation**、**Trigger** 和 **Outcome**。简而言之：

- **Motivation**：风险来源于用户或环境。用户可能无意中提出了有风险的任务，或恶意诱导代理执行不良行为；环境初始状态也可能处于不稳定或脆弱状态。例如，用户要求删除文件，却忘记环境中某些文件包含重要数据。
- **Trigger**：由于 LLM 的局限性，代理在执行过程中生成了危险动作。
- **Outcome**：最后，Motivation 被 Trigger 触发，代理执行危险动作，并产生不良后果，例如用户或环境受损。

### D.1 指标

对于安全判断测试，设数据集包含 `n` 个样本 `(x_i, y_i)`，其中 `x_i` 是输入，`y_i ∈ {0, 1}` 是输出。记 `p_θ(·)` 为语言模型，`ŷ_i = p_θ(x_i) ∈ {0,1}` 为预测标签。指标可表示为：

- Recall = `sum I(y_i = 1, ŷ_i = 1) / sum I(y_i = 1)`
- Specificity = `sum I(y_i = 0, ŷ_i = 0) / sum I(y_i = 0)`
- Precision = `sum I(ŷ_i = 1, y_i = 1) / sum I(ŷ_i = 1)`
- F1 = `2 * Recall * Precision / (Recall + Precision)`

其中 `I(·)` 为指示函数。

风险识别测试的指标见附录 D.2 中的 GPT-4 成对评估提示。

### E.2 分析补充说明

#### Few-Shot-CoT

选择 2 个示例的原因是，受限于 LLM 上下文长度。由于需要输入用户提示、模型响应以及多轮记录，单个案例本身就占用很多 token。Few-Shot 中的示例数还必须是偶数（0、2、4……）。作为二分类任务，Few-Shot 的示例需同时包含 `safe` 和 `unsafe`，这会进一步占用上下文长度。

具体而言，Llama-2 和 Vicuna 系列 4k 上下文只能容纳 2-shot 示例。如果选择 4 个或更多示例，某些长案例测试会超过上下文长度，导致比较不公平。因此，在公平条件下我们声明：“Few-Shot-CoT 并不能稳定提升总体表现。”

#### 关于“风险意识”主张

之所以采用定性分析而不是定量分析，原因如下：

- 目前关于 LLM 知识与推理能力的原则尚未充分探索，定量分析可能带来无法在论文中妥善处理的不确定性和不可解释性。
- 一般认为推理是 LLM 的涌现能力，来源于知识积累（Wei et al., 2022a），但二者并非原子且互相交织（Kojima et al., 2022; Schaeffer et al., 2024）。
- 另外，指令微调 LLM 与预训练 LLM 的评估存在差异。不同模型提供方使用不同的指令微调技术，而知识与推理相关评测主要针对预训练 LLM，但代理与代理安全监控器通常是指令微调模型。

### E.3 Llama Guard 的风险类别

我们推测 Meta-Llama-Guard-2-8B 比 LlamaGuard-7b 更好的原因，主要在于训练时覆盖了更多风险类别。

- LlamaGuard-7b 的 6 类风险：Violence & Hate, Sexual Content, Guns & Illegal Weapons, Regulated or Controlled Substances, Suicide & Self Harm, Criminal Planning。
- Meta-Llama-Guard-2-8B 的 11 类风险：Violent Crimes, Non-Violent Crimes, Sex-Related Crimes, Child Sexual Exploitation, Specialized Advice, Privacy, Intellectual Property, Indiscriminate Weapons, Hate, Suicide & Self-Harm, Sexual Content。
